# Редактирование и Удаление Школ

## Обзор

Данная документация описывает функционал редактирования данных владельцев школ и удаления школ для роли **Архитектор**.

## Новые Возможности

### 1. Редактирование Владельца Школы

Архитектор может редактировать данные главного администратора любой школы:

- **Имя администратора** - изменение отображаемого имени
- **Email администратора** - изменение email для входа (с проверкой уникальности)
- **Пароль** - установка нового пароля (опционально)

#### UI Элементы

- **Кнопка "Редактировать"** на каждой карточке школы в разделе "Управление школами"
- **Диалог редактирования** с формой для изменения данных администратора
- Отображение названия школы в режиме только для чтения
- Поле пароля опционально - можно оставить пустым, чтобы не менять

#### Валидация

- Email проверяется на корректность формата
- Новый email проверяется на уникальность в базе данных
- Пароль должен быть минимум 6 символов (если указан)
- Хотя бы одно поле должно быть изменено

### 2. Удаление Школы

Архитектор может полностью удалить школу со всеми связанными данными.

#### UI Элементы

- **Кнопка с иконкой корзины** на каждой карточке школы
- **Диалог подтверждения** с предупреждением о последствиях

#### Удаляемые Данные

При удалении школы каскадно удаляются:
- ✅ Все клиенты школы
- ✅ Все платежи клиентов
- ✅ Вся история просрочек
- ✅ Все пользователи школы (включая администратора)
- ✅ Сама школа

⚠️ **ВНИМАНИЕ**: Это действие необратимо!

## API Endpoints

### PUT /api/schools/:schoolId

Обновление данных владельца школы.

**Доступ**: Только для роли `architect`

**Параметры запроса**:
```json
{
  "adminName": "Новое имя",        // опционально
  "adminEmail": "new@email.com",  // опционально
  "adminPassword": "newpass123"   // опционально
}
```

**Ответ**:
```json
{
  "school": {
    "id": "uuid",
    "name": "Название школы",
    "createdAt": "2025-01-01T00:00:00.000Z",
    "adminName": "Новое имя",
    "adminEmail": "new@email.com"
  },
  "admin": {
    "id": "uuid",
    "email": "new@email.com",
    "name": "Новое имя",
    "role": "admin",
    "schoolId": "uuid"
  }
}
```

**Ошибки**:
- `403` - Доступ запрещен (не Архитектор)
- `404` - Школа или администратор не найдены
- `400` - Email уже используется другим пользователем
- `400` - Нет данных для обновления

### DELETE /api/schools/:schoolId

Удаление школы со всеми связанными данными.

**Доступ**: Только для роли `architect`

**Ответ**:
```json
{
  "message": "Школа успешно удалена"
}
```

**Ошибки**:
- `403` - Доступ запрещен (не Архитектор)
- `404` - Школа не найдена

## Пример Использования

### Редактирование

1. Пользователь с ролью "Архитектор" заходит в раздел "Управление школами"
2. Нажимает кнопку "Редактировать" на карточке нужной школы
3. В диалоге изменяет нужные поля (имя, email, пароль)
4. Нажимает "Сохранить изменения"
5. Система проверяет данные и обновляет информацию
6. Отображается уведомление об успехе

### Удаление

1. Пользователь с ролью "Архитектор" заходит в раздел "Управление школами"
2. Нажимает кнопку с иконкой корзины на карточке школы
3. В диалоге подтверждения читает предупреждение о последствиях
4. Подтверждает удаление
5. Система удаляет школу и все связанные данные
6. Отображается уведомление об успехе

## База Данных

### Транзакции

Обе операции используют транзакции PostgreSQL:

**Обновление**:
- Не требует транзакции (одна операция UPDATE)

**Удаление**:
```sql
BEGIN;
DELETE FROM clients WHERE school_id = $1;
DELETE FROM users WHERE school_id = $1;
DELETE FROM schools WHERE id = $1;
COMMIT;
```

### Каскадное Удаление

Платежи и история просрочек удаляются автоматически благодаря внешним ключам с опцией `ON DELETE CASCADE` в таблицах:
- `payments` -> `clients`
- `overdue_history` -> `clients`

## Тестирование

### Mock API режим

При включенном `USE_MOCK_API = true`:
- Редактирование обновляет локальный state
- Удаление удаляет из локального state
- Все изменения сохраняются только в памяти браузера

### Реальный API режим

При `USE_MOCK_API = false`:
- Все операции выполняются через реальный backend
- Изменения сохраняются в PostgreSQL
- После операций список школ перезагружается

## Рекомендации

1. **Перед удалением школы** убедитесь, что данные больше не нужны
2. **При изменении email** проверьте, что администратор знает новый email для входа
3. **При установке нового пароля** обязательно сообщите его администратору
4. **Регулярно делайте бэкапы** базы данных перед массовыми операциями
