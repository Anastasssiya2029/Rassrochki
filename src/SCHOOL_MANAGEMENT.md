# Управление школами для Архитектора

## Обзор

Архитектор имеет доступ к специальной странице управления школами, где может:
- Просматривать список всех школ в системе
- Добавлять новые школы
- Назначать главных администраторов для каждой школы
- **Редактировать данные владельцев школ**
- **Удалять школы со всеми данными**
- Выбирать школу для просмотра

## Как это работает

### 1. Страница выбора школы

После входа в систему как Архитектор, отображается специальная страница с двумя вкладками:

#### Вкладка "Выбор школы"
- Показывает список всех доступных школ
- Каждая карточка школы содержит:
  - Иконку школы
  - Название школы
  - Дату создания
- Клик по школе переводит Архитектора в режим просмотра этой школы

#### Вкладка "Управление"
- Позволяет добавлять новые школы
- Отображает детальную информацию о существующих школах:
  - Название школы
  - Дата создания
  - Имя главного администратора
  - Email главного администратора
- **Кнопка "Редактировать"** для изменения данных владельца
- **Кнопка "Удалить"** для удаления школы со всеми данными

### 2. Добавление новой школы

При нажатии кнопки "Добавить школу" открывается диалог с формой:

**Поля формы:**
- Название школы (обязательное)
- Имя администратора (обязательное)
- Email администратора (обязательное, должен быть уникальным)
- Пароль для администратора (обязательное, минимум 6 символов)

**Валидация:**
- Все поля обязательны для заполнения
- Email проверяется на корректность формата
- Email должен быть уникальным в системе
- Пароль должен быть не менее 6 символов

### 3. API Endpoints

#### GET `/api/schools`
Получить список всех школ (только для Архитектора)

**Response:**
```json
{
  "schools": [
    {
      "id": "1",
      "name": "Онлайн-школа Прогресс",
      "createdAt": "2024-01-15T00:00:00.000Z",
      "adminName": "Владелец Прогресса",
      "adminEmail": "admin@progress.com"
    }
  ]
}
```

#### POST `/api/schools`
Создать новую школу с администратором (только для Архитектора)

**Request:**
```json
{
  "schoolName": "Новая школа",
  "adminName": "Иван Иванов",
  "adminEmail": "admin@newschool.com",
  "adminPassword": "secure123"
}
```

**Response:**
```json
{
  "school": {
    "id": "4",
    "name": "Новая школа",
    "createdAt": "2024-11-15T00:00:00.000Z",
    "adminName": "Иван Иванов",
    "adminEmail": "admin@newschool.com"
  },
  "admin": {
    "id": "10",
    "email": "admin@newschool.com",
    "name": "Иван Иванов",
    "role": "admin",
    "schoolId": "4"
  }
}
```

### 4. База данных

При создании новой школы происходит:

1. Создание записи в таблице `schools`:
```sql
INSERT INTO schools (name) VALUES ($1) RETURNING *;
```

2. Создание записи администратора в таблице `users`:
```sql
INSERT INTO users (email, password_hash, name, role, school_id) 
VALUES ($1, $2, $3, 'admin', $4) 
RETURNING id, email, name, role, school_id;
```

## UI/UX

### Дизайн
- Минималистичный стиль в духе Apple
- Градиенты и тени для создания глубины
- Плавные анимации при взаимодействии
- Отзывчивый дизайн

### Цветовая схема
- Основной градиент: от `#7B68EE` до `#4F9CF9`
- Акцентный градиент: от `#FB923C` до `#FF6B9D`
- Фон: `#F7F8FA`
- Текст: `#1F2937` (темно-серый)

### Интерактивность
- Hover эффекты на карточках школ
- Анимация при переходе между вкладками
- Плавное появление/исчезание диалогов
- Toast уведомления об успешных действиях или ошибках

## Безопасность

- Только пользователи с ролью `architect` могут создавать школы
- Пароли администраторов хешируются с использованием bcrypt
- Проверка уникальности email перед созданием администратора
- Все API endpoints защищены JWT токеном
